# แผนพัฒนา: ระบบจัดการฐานข้อมูลเข้าใจง่าย ระบบลบนักเรียน และตรวจผลสอบก่อนเรียนรายข้อแบบละเอียด

แผนการปรับปรุงระบบหลังบ้าน (Teacher & Admin Management) ของเกมการเรียนรู้ผจญภัย 5 ด่าน โดยปรับเปลี่ยนการแสดงผลทางเทคนิคเดิมให้เป็นมิตรกับคุณครู ใช้งานง่าย ปลอดภัย และแสดงข้อมูลการเรียนรู้ของนักเรียนอย่างครบถ้วน

---

## User Review & Critical Decisions

> [!IMPORTANT]
> สรุปผลการตัดสินใจจาก Phase 1 และแนวทางการพัฒนา:

- **Confirmed Decision (โครงสร้างฐานข้อมูล)**: ผู้ใช้เลือก **"เปลี่ยนเป็นแดชบอร์ดสรุปสถิติพร้อมปุ่มจัดการข้อมูลที่เข้าใจง่าย"** โดยนำกล่องแสดงโครงสร้างทางเทคนิคเดิม (Schema Tables / PK / FK) ออกจากหน้าแรก แล้วแทนที่ด้วยแผงสรุปสุขภาพฐานข้อมูล (Database Health & Overview Stats) พร้อมปุ่มคำสั่งหลัก เช่น สำรองข้อมูล (Backup), กู้คืนข้อมูล (Restore), และการล้างข้อมูลอย่างปลอดภัย
- **Confirmed Decision (ระบบลบนักเรียน)**: เพิ่มปุ่ม "ลบนักเรียน" ทั้งในหน้ารายการผู้เล่นและหน้าโปรไฟล์นักเรียน พร้อมระบบยืนยันความปลอดภัย 2 ชั้น (Modal ยืนยันระบุชื่อผู้เล่น) พร้อมทำการลบข้อมูลแบบ Cascading (ลบข้อมูลผู้เล่น, ความคืบหน้า, บันทึกคำตอบ, ประวัติการเล่น, ธุรกรรม) และบันทึกลงใน `admin_audit_logs`
- **Confirmed Decision (ตรวจผลสอบก่อนเรียน 7 ข้อ)**: เพิ่มระบบบันทึกและแสดงผลการตอบคำถามก่อนเรียน (Pre-test) 7 ข้ออย่างละเอียด แสดงทั้งข้อความโจทย์, ตัวเลือกที่นักเรียนตอบ, เฉลยที่ถูกต้อง, สถานะถูก/ผิด (✓/✕), และคำอธิบายเหตุผล พร้อมเปิดดูได้ทั้งจากตารางผู้เล่นและในโปรไฟล์นักเรียน

## 1. Overview & Core Concept

- **What It Does**: 
  1. จัดระเบียบหน้าจัดการฐานข้อมูลแอดมินใหม่ นำบล็อกผังโครงสร้างเทคนิค (Schema Box) ออก แทนที่ด้วยแผงควบคุมสถิติฐานข้อมูลที่เป็นมิตร เข้าใจง่ายในพริบตา
  2. เพิ่มฟังก์ชันลบนักเรียน (Delete Student) สำหรับคุณครู/แอดมิน พร้อมกล่องข้อความยืนยัน เพื่อป้องกันการกดพลาด และบันทึกประวัติผู้ลบใน Audit Log
  3. เพิ่มระบบดูข้อมูลการตอบคำถามก่อนเรียน (Pre-test Review Modal) ทั้ง 7 ข้อแบบละเอียดรายบุคคล แสดงข้อที่ตอบถูก ข้อที่ตอบผิด ตัวเลือกของนักเรียน เฉลยที่ถูกต้อง และคำอธิบายรายข้อ
- **Target Audience**: คุณครูผู้สอน, แอดมินโรงเรียน และผู้ดูแลระบบการเรียนรู้ STEM
- **Key Value**: ครูสามารถตรวจสอบจุดอ่อน-จุดแข็งของนักเรียนก่อนเริ่มเรียนได้ทันที และบริหารจัดการรายชื่อนักเรียนได้อย่างสะดวก ปลอดภัย โดยไม่ต้องเจอกับโค้ดหรือโครงสร้างทางเทคนิคที่ซับซ้อน

## 2. User Experience & Visual Design

- **Visual Identity & Theme**:
  - ยึดธีมหลักของระบบเดิม: **เหลืองทอง Chibi แฟนตาซี (Golden Amber & Cream)**
  - Palette: สีทองสดใส (`#F59E0B`), ครีมละมุน (`#FFFBEB`, `#FFFDF7`), ขอบนุ่มมน (`rounded-2xl` ถึง `rounded-3xl`), เงาสีอำพันนุ่มนวล
  - ไม่มีเส้นขอบหนาด้านเดียว และไม่มี Badge Capsule ซ้อนทับที่ไม่จำเป็น (ปฏิบัติตาม Frontend Design Constitution)
- **Key User Flows**:
  1. **Flow A: ดูแดชบอร์ดฐานข้อมูลแบบเข้าใจง่าย (Clean Database Overview)**
     - เข้าแท็บหน้าหลัก / ฐานข้อมูล จะพบการ์ดสรุปสถานะระบบ: จำนวนผู้ใช้งาน, สถิติการทำข้อสอบก่อนเรียน, พื้นที่การจัดเก็บ, และแถบปุ่มจัดการด่วน (ส่งออกไฟล์ข้อมูล JSON, ล้างแคชทดสอบ, สรุปความปลอดภัย)
  2. **Flow B: ลบนักเรียนออกจากระบบ (Delete Student with Safety)**
     - ครูคลิกปุ่มถังขยะสีแดง "ลบ" ที่แถวของนักเรียน หรือในหน้าต่างโปรไฟล์
     - หน้าต่างป๊อปอัปแจ้งเตือนสีส้ม-แดง แสดงชื่อ-นามสกุล, รหัสผู้เล่น และคำเตือน
     - ครูพิมพ์ยืนยันหรือกด "ยืนยันการลบนักเรียน"
     - ระบบลบข้อมูลทุกตารางที่เกี่ยวข้อง บันทึก Audit Log และแสดงแจ้งเตือน "ลบข้อมูลนักเรียนสำเร็จ"
  3. **Flow C: ตรวจข้อสอบก่อนเรียนรายบุคคล (Detailed Pre-test Review)**
     - ครูคลิกปุ่ม "ตรวจข้อสอบก่อนเรียน" (ไอคอน 📝 หรือปุ่มในตาราง)
     - หน้าต่างป๊อปอัปจะแสดงผลวิเคราะห์ 7 ข้อ:
       - สรุปคะแนนรวม (เช่น 6/7 ข้อ) และเวลาที่ทำแบบทดสอบ
       - การ์ดคำถามทั้ง 7 ข้อ แสดงหมวดหมู่วิชา (วิทย์ / เทคโน / วิศวะ / คณิต)
       - ตัวเลือกที่นักเรียนเลือก (มีสัญลักษณ์ ✓ สีเขียวถ้าถูก, ✕ สีแดงถ้าผิด)
       - เฉลยที่ถูกต้องพร้อมเน้นสีเขียวอ่อน
       - กล่องคำอธิบายความรู้ STEM เพิ่มเติม

## 3. Key Product Decisions & Trade-Offs

- **Decision 1: นำ Schema Diagram ออกจากหน้าแรก แล้วแทนที่ด้วย Quick Operations & Metrics**
  - *Chosen Approach*: เปลี่ยนพื้นที่ด้านขวาบนเดิมที่เป็นกล่อง Users, Player_Progress, Play_History แบบเทคนิค ให้กลายเป็น **"ศูนย์สรุปและจัดการฐานข้อมูลสำหรับคุณครู" (Database Operations & Health Hub)** ประกอบด้วยตัวชี้วัดความพร้อมของระบบ, สรุปผลสอบก่อนเรียนของทั้งห้อง, และปุ่มสำรองข้อมูล
  - *Why*: ครูผู้สอนต้องการทราบภาพรวมของนักเรียนและการจัดการข้อมูล ไม่จำเป็นต้องดูชื่อ Foreign Key หรือ Data Type ทางเทคนิค
- **Decision 2: โครงสร้างการจัดเก็บข้อมูลการตอบคำถามก่อนเรียน (Pre-test Detailed Storage)**
  - *Chosen Approach*: เพิ่มฟิลด์ `pretest_answers` ใน `UserRecord` และสร้างตาราง/อินเตอร์เฟซ `PretestResponseRecord` ในระบบฐานข้อมูล เพื่อบันทึกคำตอบจริงที่นักเรียนเลือกครบทั้ง 7 ข้อ รวมทั้ง Seed ข้อมูลจำลองที่สมจริงให้นักเรียนทุกคนที่มีสถานะ `pretest_completed: true`
  - *Why*: ทำให้สามารถดึงข้อมูลมาแสดงผลได้ทันทีโดยไม่ต้องคำนวณใหม่ และข้อมูลคงทนอยู่แม้จะรีเฟรชหน้าเว็บ
- **Decision 3: ความปลอดภัยในการลบข้อมูล (Cascading Deletion with Audit)**
  - *Chosen Approach*: ฟังก์ชัน `deleteUser(userId, adminName)` จะลบข้อมูลจาก `users`, `player_progress`, `play_history`, `answer_logs`, `play_sessions`, `wallet_transactions` ทั้งหมด เพื่อไม่ให้เกิดข้อมูลกำพร้า (Orphan Data) พร้อมบันทึก Action ลงใน `admin_audit_logs`
  - *Why*: รักษาความสมบูรณ์ของฐานข้อมูล (Referential Integrity) และตรวจสอบย้อนหลังได้ว่าใครเป็นผู้ลบ

### Data Schema Extensions (`src/types/database.ts` & `src/services/database.ts`)

```typescript
export interface PretestAnswerItem {
  question_id: number;
  category: string;
  category_label: string;
  question_text: string;
  selected_choice_index: number;
  selected_choice_text: string;
  correct_choice_index: number;
  correct_choice_text: string;
  is_correct: boolean;
  explanation: string;
}

// UserRecord extension
export interface UserRecord {
  // ... existing fields
  pretest_completed: boolean;
  pretest_score: number;
  pretest_date?: string;
  pretest_answers?: PretestAnswerItem[]; // Detailed record for all 7 questions
}
```
